# AGENTS.md — Coding Agent 执行入口（v1.2）

## 身份
你是实现与验证代理。按 `specs/plan-5days.md` 当天的任务实现。文件和测试结果才是进度的证据，不是聊天记忆。

## 每天的流程（按天批准，不是按任务）
1. **开始**：读 `specs/constitution.md`、`specs/plan-5days.md` 当天部分、相关 `specs/0x-*.md`；输出 `git status`、当前分支与 HEAD；给出当天计划（任务、文件、验证命令）。等用户说"开始"。
2. **实现**：按任务顺序做，每完成一个任务提交一次 commit（commit message 写任务 ID）。
3. **结束**：按下面模板汇报；更新 `reports/progress.md`。

## 当天汇报模板
```text
Day N / 完成的任务:
变更文件:
运行的命令与结果（含 exit code）:
真实数据上的数字（若有）:
未完成 / 未验证:
明天第一件事:
```

## 必须遵守
- 每个任务至少一个正常路径测试和一个失败路径测试；涉及时间切分、已见过滤、CAS 的任务必须有反例测试。
- 不得宣称运行过没有运行的命令；区分"已实现 / 已测试 / 未验证"。
- 调参只看 validation；test 只在 Day 5 的 T14 跑**一次**。
- 不为了让测试通过而修改评估口径、降低门槛或删测试。
- 不在日志、事件、发布包里写原始 user_id 或评论原文；示例与 fixture 只用合成数据。
- 晋升与回滚默认 dry-run，写指针必须显式 `--execute`。
- 不提前实现 v1.2 范围外的东西（融合、时序、Drift、Dashboard 等）。
- 新写的 Python 代码文件保持 ASCII（注释用英文），文档可以用中文。

## 落后时
按 `specs/plan-5days.md` 的"砍单顺序"砍，砍之前告诉用户。不要为赶进度跳过评估器的 Golden 测试或时间切分反例测试。

## 遇到规格冲突或不明确
写下两种方案和影响，问用户；不依赖该点的部分继续做。v1.2 没写到的细节可以参考 v1.1 对应章节，但不能把 v1.2 已简化或延后的要求加回来。
