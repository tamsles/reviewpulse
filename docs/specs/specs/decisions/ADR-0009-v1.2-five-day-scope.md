# ADR-0009 — v1.2：5 天范围裁剪

- 状态：**ACCEPTED**（2026-11-21 用户审核，D1–D7 全部批准；设计取舍已批准，尚未实现或验证）
- 取代：v1.1 中与下列决策冲突的部分（ADR-0005 的部署核验部分、ADR-0006 的双密钥部分、REC-01/03 的 RecBole 要求、GATE-04）
- 不变：ADR-0007 第 1–7 条（离线评估口径）全部沿用；ADR-0006 的"上线产物 = 门禁评估的同一产物，训练窗口终点 ≤ train_end"沿用

## 背景
v1.1 有 30 个任务，按生产系统标准设计。项目实际约束：一个人、5 天、作为日本 Web 公司新卒求职作品，开发者需要在面试中解释每个设计。

## 决策

| ID | 决策 | 放弃的东西 | 理由 |
|---|---|---|---|
| D1 | 范围 = P0 闭环；Day 5 有余力加离线情感分类 | 融合、时序、Drift、反馈、Dashboard | 路线图本身说 M3 即可作为简历项目 |
| D2 | BPR 用自写 PyTorch 实现，不用 RecBole | RecBole 的现成模型库（LightGCN 等） | 兼容风险高；自写 BPR 约 100 行，面试好讲；评估本就用自有评估器 |
| D3 | 一把 HMAC 密钥 `RP_USER_KEY` 同时用于发布包与事件 | 发布包与遥测密钥隔离 | 数据集 user_id 已匿名；单机演示无多团队权限边界 |
| D4 | 去掉 desired/actual 部署记录与 `deploy verify`；晋升后重启服务生效，用 `/ready` 确认 | 部署失败的可审计记录 | 单机单进程，额外一层主要是代码量 |
| D5 | 去掉 GATE-04 Champion 重评估；切分不同直接拒绝 `SPLIT_MISMATCH` | 跨切分比较 | 没有反馈重训，切分不会常规变化 |
| D6 | 新建 `reviewpulse` 仓库，移植旧项目思路而非在旧分支上改 | 连续的 Git 历史 | 仓库历史干净，面试官易读 |
| D7 | Agent 按天批准，而不是按任务批准 | 细粒度审核 | 30 轮审批不现实 |

## 后果
- 简历/README 必须写清楚"这是单机演示，以下是生产化还需要的东西"，并链接 v1.1 设计。
- 若以后要加 LightGCN，需要重新评估是否引入 RecBole（新 ADR）。
- 若以后加反馈重训，需要先实现 GATE-04（v1.1 已有设计）。
